## 部署到宝塔（Linux）报 cannot execute binary file

- 用户把 `bin/beiyun-server` 传到 `/www/wwwroot/byyd/beiyun-server` 后执行报错。根因：macOS 上 `go build` 出的是 **Mach-O arm64**，Linux 内核不认。不是权限问题（那会是 Permission denied）。
- 修法：`CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ...`。能免 CGO 是因为 SQLite 用的是 `modernc.org/sqlite`（纯 Go），产物静态链接，CentOS 7 也不缺 glibc。amd64/arm64 各出一份（`uname -m`：x86_64 → amd64，aarch64 → arm64）。
- 已固化成 `npm run build:linux` / `build:linux:amd64` / `build:linux:arm64`，产物 `bin/beiyun-server-linux-<arch>`（`bin/` 已忽略，不入库）。
- 验证方式：Docker 起 `alpine:3.20`，挂载 `bin/` 只读，容器内后台跑二进制 + `wget` 打 `/healthz`、`/foo`、`/api/v1/nope`——两个架构都返回 `{"db":"ok","status":"ok"}`、SPA 回退 200、API 404。macOS 上无法直接执行 ELF，容器是唯一能真跑的办法。
- 宝塔要点（已写进 README）：面板「Go 项目」项目目录 `/www/wwwroot/byyd`、启动文件 `beiyun-server`、端口与 `BEIYUN_ADDR` 一致；`BEIYUN_DB_PATH=/www/wwwroot/byyd/data/app.db`；`data` 属主必须是运行用户（默认 `www`），否则 SQLite 打不开直接退出；绑 `127.0.0.1` 让 Nginx 反代，否则 8787 直连公网且 XFF 可伪造导致限流失效。
- 顺手确认：`scp` 覆盖同名文件不需要先删，面板停项目→覆盖→启项目即可更新；回滚就是换回上一个二进制，数据库迁移只做加法。

## 宝塔 nginx 配置 + 修复 XFF 伪造

- 用户问宝塔上 nginx 怎么写。写配置前先发现代码有个洞：`clientIP()` 取 `X-Forwarded-For` **最左一段**，而 `$proxy_add_x_forwarded_for` 恰好把客户端自带的头留在最左 → 客户端可自选来源 IP，限流等于没有。
- 修法（`internal/api/api.go`）：只有直连方是 loopback 才读转发头，且取**最右一跳**（nginx 追加的那段）；非本机直连一律用 `RemoteAddr`。这样无论对面配 `$proxy_add_x_forwarded_for` 还是 `$remote_addr`，都拿得到真实 IP。
- 验证靠 Docker：容器里绑 `0.0.0.0` 并映射端口，宿主机直连带 `X-Forwarded-For: 1.2.3.4`，日志记的是真实对端 `172.17.0.1`（伪造被忽略）；`docker exec` 在容器内走 loopback 带 `8.8.8.8`，日志记 `8.8.8.8`（可信）。**这是唯一能测「非 loopback 对端」的办法**，本机直接跑永远是对端 loopback。
- 新增 `server/deploy/nginx.bt.conf.example`：保留宝塔的 `#SSL-START/#SSL-END` 与伪静态 `include` 两段（面板在维护，别整体覆盖），`location /` 反代 + `client_max_body_size 64k` + `gzip_proxied any` + `location = /healthz { access_log off; }`。
- 三个要点写进 README：① 不要配 `root`/`try_files`（产物已内嵌，SPA 回退和 `/_nuxt/` immutable 缓存头都是 Go 设的）；② 转发头用 `$remote_addr` 覆盖；③ healthz 关日志。另外提示面板「反向代理」UI 生成的文件用的是 `$proxy_add_x_forwarded_for`，要手工改一行。
