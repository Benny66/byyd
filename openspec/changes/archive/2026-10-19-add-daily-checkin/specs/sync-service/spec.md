## ADDED Requirements

### Requirement: 单二进制交付

服务 SHALL 以单个可执行文件交付，内嵌前端构建产物并提供 HTTP 服务；启动时 MUST 只需可执行文件、数据目录与监听地址三项配置；未知路径 MUST 回退到前端入口页而不是返回服务器默认错误页。

#### Scenario: 启动

- **WHEN** 在有持久磁盘的服务器上执行二进制并指定数据目录
- **THEN** 前端页面与接口同时可用，无需额外的静态文件目录

#### Scenario: 未知路径

- **WHEN** 访问 `/foo`
- **THEN** 返回前端入口页，应用正常渲染

#### Scenario: 静态资源缓存

- **WHEN** 请求带内容哈希的构建资源
- **THEN** 返回长期缓存头；入口页返回不缓存头

### Requirement: 接口契约

服务 SHALL 在 `/api/v1` 下提供设备注册与更新、设备删除、训练记录上报、榜单查询与健康检查接口；响应 MUST 为 JSON，错误 MUST 使用统一错误码结构；接口版本变化 MUST 通过路径前缀区分。

#### Scenario: 设备注册

- **WHEN** 提交设备 ID 与昵称
- **THEN** 返回设备信息，重复提交同一设备 ID 视为更新

#### Scenario: 训练上报

- **WHEN** 提交一条合法记录
- **THEN** 返回成功状态与新记录标识

#### Scenario: 错误结构

- **WHEN** 请求参数非法
- **THEN** 返回对应 4xx 状态与包含 code、message 的 JSON 错误体

#### Scenario: 未知接口

- **WHEN** 请求不存在的 `/api/v1/*` 路径
- **THEN** 返回 404 JSON 错误，不回退到前端页面

### Requirement: 幂等写入

训练记录上报 MUST 以“设备 ID + 记录 ID”为唯一键；重复上报同一条记录 MUST 返回成功语义且不产生重复数据；客户端重试 MUST 安全。

#### Scenario: 重试同一记录

- **WHEN** 同一条记录连续上报两次
- **THEN** 第二次返回成功且不新增记录，榜单统计不变

#### Scenario: 不同记录同 ID

- **WHEN** 两台设备各自上报相同记录 ID
- **THEN** 两条记录分别保存，互不覆盖

### Requirement: 数据持久化与备份

服务 SHALL 把数据持久化到单个数据库文件，启用 WAL 与写超时；启动时 MUST 自动执行未应用的迁移，MUST NOT 因数据库为空而失败；系统 SHALL 提供可定时执行的备份方式，且备份不影响在线读写。

#### Scenario: 首次启动

- **WHEN** 数据目录为空
- **THEN** 自动建表并正常提供服务

#### Scenario: 重启保留数据

- **WHEN** 服务重启
- **THEN** 设备、记录与榜单统计保持不变

#### Scenario: 在线备份

- **WHEN** 服务运行中执行备份
- **THEN** 生成一致的数据库副本，读写不中断

### Requirement: 限流与容量

服务 SHALL 对单 IP 请求速率与单设备每日上报条数设上限，超出时 MUST 返回 429 或明确的拒绝错误，且 MUST NOT 影响其他设备；榜单查询 MUST 限制返回条数上限。

#### Scenario: 触发限流

- **WHEN** 同一 IP 每分钟请求超过阈值
- **THEN** 返回 429，客户端退避重试

#### Scenario: 榜单条数

- **WHEN** 请求榜单时指定超过 100 条
- **THEN** 服务端按上限 100 截断

### Requirement: 健康检查与可观测

服务 SHALL 提供健康检查接口，返回服务与数据库状态；MUST 输出结构化访问日志，包含路径、状态码、耗时与请求标识；日志 MUST NOT 记录昵称以外的个人信息。

#### Scenario: 健康检查

- **WHEN** 请求健康检查接口
- **THEN** 返回 200 与数据库可用状态

#### Scenario: 数据库不可用

- **WHEN** 数据库文件不可写
- **THEN** 健康检查返回非 200，并记录错误日志

### Requirement: 时间基准

服务 MUST 以 Asia/Shanghai 作为业务时区判断“今天”与周窗口；记录归属日 MUST 落在服务端今天的 7 天前到 1 天后之间（7 天用于开启上榜时补传历史），超出范围 MUST 拒绝；服务端时间与客户端时间不一致时，以服务端为准。

#### Scenario: 客户端时钟偏快

- **WHEN** 客户端上报的归属日比服务端今天晚 2 天
- **THEN** 拒绝该记录

#### Scenario: 跨零点容错

- **WHEN** 客户端上报的归属日为服务端昨天
- **THEN** 接受该记录

#### Scenario: 补传历史

- **WHEN** 客户端开启上榜时上报 6 天前的记录
- **THEN** 接受该记录，且最多为该天贡献 1 个有效训练日

#### Scenario: 过旧记录

- **WHEN** 客户端上报 8 天前的记录
- **THEN** 拒绝该记录

### Requirement: 发布与回滚

前端构建产物与服务端 MUST 作为同一版本发布；回滚 MUST 只需替换二进制并重启，数据库迁移 MUST 保持向后兼容，旧版本二进制 MUST 能读取新库。

#### Scenario: 发布

- **WHEN** 部署新版本
- **THEN** 同一次发布中包含匹配的前端产物与接口实现

#### Scenario: 回滚

- **WHEN** 新版本出现问题
- **THEN** 换回上一版二进制即可恢复，无需回滚数据库
