## MODIFIED Requirements

### Requirement: 预渲染静态站点

系统 SHALL 在构建时预渲染所有路由（当前仅 `/`）为静态 HTML 与静态资源；产物 MUST NOT 依赖 Node 运行时，但 MUST 由 Go 服务内嵌并在同一进程内提供；预渲染出错时 MUST 让构建失败。

#### Scenario: 产物形态

- **WHEN** 执行构建
- **THEN** 输出入口 HTML 与带内容哈希的静态资源，可被服务端完整内嵌

#### Scenario: 构建失败即报错

- **WHEN** 预渲染过程中出现错误
- **THEN** 构建以失败状态结束，不产出可误发布的残缺产物

#### Scenario: 前端与接口同源

- **WHEN** 页面在浏览器中加载
- **THEN** 页面与 `/api/v1` 由同一服务提供，不依赖额外域名或静态托管

### Requirement: 导出发布目录

系统 SHALL 提供发布步骤：把构建产物复制到发布目录、同步到服务端内嵌目录、编译出单个可执行文件；构建产物缺少入口 HTML 时 MUST 报错退出；发布产物 MUST 同时包含前端资源与服务实现，且版本一致。

#### Scenario: 导出内容完整

- **WHEN** 执行发布构建
- **THEN** 生成包含前端资源与接口实现的单个可执行文件

#### Scenario: 同步前端资源

- **WHEN** 前端构建产物更新
- **THEN** 内嵌目录被完整替换，不残留上一版本的文件

#### Scenario: 缺少构建产物

- **WHEN** 未先执行前端构建就编译服务端
- **THEN** 构建脚本报错并以失败状态退出

#### Scenario: 导出统计

- **WHEN** 发布构建完成
- **THEN** 输出可执行文件大小与内嵌资源数量，便于确认版本

## REMOVED Requirements

### Requirement: 静态托管兼容

**Reason**: 引入登录态无关的排行榜后，前端需要与 API 同源部署，纯静态托管无法提供训练记录写入与榜单查询；未知路径兜底改由 Go 服务处理。

**Migration**: 使用单二进制部署到带持久磁盘的服务器，由服务端提供入口页兜底；原 GitHub Pages 部署方式不再受支持。
